# 输入补齐契约

路由器仅补齐有确定依据的字段：

自然语言入口按 [AI 理解与程序校验](semantic-input.md) 执行。公共规范化处理中文标点、口语时刻和有依据的日期省略；自由句式可由 AI 提供带原文引用的 `--interpretation`，但必须通过原文哈希、固定时间基准及时间事实校验。原始上下文头不参加改写。

- 走查测试：正文明确包含“走查测试”才使用独立解析器，需同 VIN 的两个完整、不重叠时段，不接受结果表 URL。显式角色标签优先，否则按输入顺序绑定 Base 与 PCM更新；不按时间先后交换。`ready` 不代表运行依赖已就绪，须通过该 Skill 的本机预检后才能启动。
- Uroad：规范化日期分隔符、中文冒号、口语时刻并补齐秒数；“今天/昨天/前天”以固定的首次时间基准为准；支持“起点后 N 分钟”和“事件时刻前后各 N 秒”。普通范围完全没日期时先询问；原有时刻加时长当天约定保留并明确记录。
- AD P99：用户明确标注 Baseline/base/基线/刷包前/替换前与 PCM更新/替换后/刷包后/更新后时，按标注绑定时间窗和对应 Sheets；未标注角色时，按用户消息中的输入顺序，第一组为 Base（Baseline），第二组为 PCM 更新，即使第一组时间更晚也不交换。两份 Sheets 与其各自时间窗一起绑定；时间排序只用于检查时间窗重叠，不用于分配角色。

以下字段绝不猜测：VIN、缺失的时间窗、第二份 Sheets、线上读取身份。缺失时只发起澄清问题，不创建任务，不下载数据。

本机已通过 CC Connect 的阿斯加德后台桥接处理双时段 `fsdlog` 派发和结果卡片轮询；路由命中 `ad-p99-asgard,status=ready` 时按活动桥接流程提交。
