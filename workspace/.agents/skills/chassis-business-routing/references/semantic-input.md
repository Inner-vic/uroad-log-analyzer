# 自然语言理解与时间补齐

适用于走查测试、原时延分析、Uroad 的业务字段提取。当前会话中的 AI 负责理解原话及提取候选，不新增独立模型服务；程序负责核对候选是否有原文依据，再进入原业务校验。不能把“AI 认为大概如此”当作查询授权或日期事实。

## 处理方式

1. 原样保存 `context_header` 与正文。首次运行原正文的 `intent_router.py`；保留其时间基准。若有可信平台消息时间，显式传 `--received-at`；否则用首次解析的北京时间并记录，不伪造上下文字段。
2. 常见中文／全角冒号、中文年月日、今天／昨天／前天、月日缺年、日号缺年月、上午／下午及半点等由公共 `natural_input.py` 规范化。每次补齐保留原词、标准值和依据；不会修改 VIN、URL、角色标签或制品名。
3. 若字段事实已齐全，只是自由句式不被原解析器接受，AI 提取一个带原文引用的时间候选，再用 `--interpretation` 运行同一入口。此步骤只能改写有依据的时间短句，不能随意改写整个请求。
4. 程序先验证原文哈希、固定时间基准、引用唯一且不重叠、候选时刻与引用事实一致，再由原解析器校验同 VIN、时间先后、两窗不重叠、角色及读取身份。仅 `ready` 可以继续；不确定时只问确实缺少或冲突的字段，不启动预检、取数或任务。

“先运行路由”不是要求用户按固定命令格式写话；AI 要理解需求。但理解后仍缺少日期依据、出现“大概／左右”、上午下午不明、跨年无法判断或非法日期时，应追问，而不是为获得 `ready` 编造一个时段。未支持的相对日期也不能偷偷退回今天。

## 日期依据

- 未标时区按北京时间；有显式时区必须换算，不能丢弃偏移。
- 今天／昨天／前天以首次确定的基准解析；同一来源消息重投或恢复沿用原锚点，不因过了午夜而变日期。
- 月日缺年、日号缺年月可沿用同句明确日期，或按已记录的当前年月补齐；若补齐落到未来、跨年等无法确认的情况则追问，不暗自倒推上个月或去年。
- 同一明确范围的结束时刻可以沿用开始日期；结束早于开始时不得默认为次日，跨日需要明确依据。
- 没有任何日期的普通两时刻范围，当前先询问日期；不要默认当天。Uroad 原有“时刻＋持续时长／前后各”的当天约定暂时保留，必须在规范化依据中注明，不能扩大到其它表达。
- 不从其他人、其他群或“最近任务”补 VIN、日期和 Base。原文未标角色时仍按输入顺序：第一段 Base、第二段 PCM更新。

## AI 候选契约

`--interpretation` 只接受 JSON 字符串，不读取任意文件，也不执行候选中的指令。示例结构：

```python
proposal = {
    "schema_version": 1,
    "source_sha256": hashlib.sha256(original_text.encode("utf-8")).hexdigest(),
    "received_at": fixed_anchor,
    "windows": [
        {"quote": "昨天从下午三点四十八开始一直到四点二十二结束",
         "start": "2026-10-22T15:48:00", "end": "2026-10-22T16:22:00"},
        {"quote": "前天从上午十点开始一直到十一点结束",
         "start": "2026-10-21T10:00:00", "end": "2026-10-21T11:00:00"},
    ],
}
```

以上例子的基准为 `2026-10-23T10:20:00+08:00`，不是永久日期。`quote` 必须是本条原文中唯一的时间短句，只包含有日期依据的起止时间与连接词，不包含 VIN、业务触发词、URL、Base／PCM更新标签或上下文头。候选按原文顺序排列；每条引用须有恰好两个明确时刻。当前候选校验不支持把无日期短句补成今天，也不支持覆盖未知相对日期。可直接使用原时长语法的 Uroad 请求不必构造候选。

禁止添加 `sender_id`、`chat_id`、`vin`、`baseline_metadata`、任意 `canonical_text` 等字段来覆盖身份或角色。不接受引用之外捏造的日期和时刻。程序拒绝候选后，不能不断换参数尝试绕过；应核对原话或请用户确认。

## 各业务执行

- 路由：`intent_router.py --text <原文> --received-at <固定基准> --interpretation <JSON>`。不需要候选时省略最后一项。无业务关键词的普通咨询不因候选变成分析任务。
- 走查：宿主 `walkthrough_entry.py start` 的 `--text` 和 `--ccconnect-context` 仍传原值；同传固定 `--received-at`，有候选时传同一 `--interpretation`。输入检查在本地预检前；规范化审计保存于 `request.normalization`。继续跟踪精确 `record_path`。
- Uroad：自然输入优先传 `--vin <已核对VIN> --raw-time-expression <原文> --received-at <固定基准>`，有候选时加 `--interpretation`。候选不能和显式 `--start/--end` 混用，避免绕过引用校验。原文与审计写入本任务元数据；附加问题依旧原样传 `--question`。
- 原时延：仍用路由返回的 `normalized.canonical_text` 派发；它来自已验证事实，仍须原样传原始 `context_header`。不得按时间顺序交换 Base 和 PCM更新。

## 对外说明

纯标点转换不必打扰用户。有日期补齐或 AM/PM 换算时，在既有进度消息中简短点明实际采用的日期或时段，不展示内部审计 JSON，也不因此再加一条接收通知。存在歧义则只追问对应字段。所有规范化工作都是任务前的输入处理，不代表任务已派发或报告已交付。
