# Uroad 日志任务生命周期

## 受理与来源

一次完整请求固定 VIN、完整起止时间、环境策略、分页限制、平台及原始飞书来源。只有同一来源 message_id 的重复投递才幂等复用；维护恢复必须指定已验证的任务，不按最近记录匹配。排队、worker 领取和子进程启动均保留同一份请求及执行选项，不能在队列启动时以默认值替换。

## 查询与环境

auto 先查询 Prod。成功响应明确返回空数据、或者该环境缺少必要日志时，整份 Uroad 报告才转 Test；同一报告内 Uroad 与 CAN 保持同一环境。`success:true,data:null` 是合法空结果。鉴权、网络、HTTP 或业务错误，以及缺少成功标记、错误 data/list/records/total 格式均为异常，不能当作空数据切环境。明确成功 code 只接受数字或数字字符串 0、200；其他业务 code 不冒充成功。

## 执行与数据

普通请求只负责依赖预检、持久化入队及唤起独立任务服务。初始 run.json 在注册事务发布 queued 前完成写入，后台领取以后，受理进程不再写该任务运行状态。Windows 调度任务每分钟检查，并允许入口立即唤起；同一调度实例不重叠。前台进程结束与后续聊天消息不能取消由任务服务拥有的执行进程。

完整时间范围只执行一次，不按时间切片。Uroad 和 CAN 两个分支并行，任一失败后等待所有已拥有的子进程退出，再记录任务终态。每个子步骤单独计时与限时；固定进度只记录阶段、计数和耗时，不放日志内容或下载地址。

Uroad 按来源、上下文、节点、时间索引完成关联。CAN 可直接流式解析；Parquet 备用链路冻结同任务来源清单、逐文件下载并记录 SHA256，以有界批量读入、目标信号筛选、SQLite 排序及完整唯一点去重替代全量内存 ASC。纳秒及无法证明兼容的 schema 保留原逐行规则。时间边界、原始行序、通道与 1 毫秒去重口径保持不变。

## 合并、报告与交付

只有两个分支都通过来源和结果合同检查才合并。HTML 生成、内容校验和工件校验通过后登记 execution=completed；附件交付仍是独立 pending/sent/delivery_failed 状态。追问上下文登记失败不阻止已校验标准报告交付。未校验的 HTML 不发送。

原生投递使用本任务来源会话及报告路径。发送前后由任务级跨进程锁串行保护；原生 CLI 退出成功并返回既定同步发送确认，才登记绑定来源、报告哈希和会话的送达凭据。失败补发只发送已有报告，不重新查询、下载或解析。

## 恢复与取消

普通槽位保存进程 PID 与随机所有权令牌，释放时验证原文件身份和令牌，不能删除已换主的槽位。健康检查按任务判断，不因另一任务仍在运行而跳过全部检查：已证明进程退出、没有执行证据的旧领取可以安全重排；已开始执行的任务不自动重排，先确认所属子进程退出、归档旧状态并保留输入，记录明确中断原因。状态或来源无法验证时拒绝自动接管，不能猜测或覆盖。启动检查失败的 worker 关闭自己的未执行领取，防止任务长期停在 claimed。

业务请求不执行过期数据清理，原有每日独立保留期任务负责清理。合并只复制需要移除字段的顶层容器，不对数百 MB 的原始分析 JSON 再序列化、反序列化一遍；原记录不修改，完整证据仍逐条写入任务内 SQLite。

普通失败保留已有证据，不能覆盖旧失败记录。已完成 Uroad、仅 CAN 失败时，可以在严格同任务绑定与哈希校验后恢复冻结 CAN 缓存。已完成的 CAN 索引、JSON 和收据保留原路径。

恢复进程意外退出时，只有证明原进程与拥有的子步骤均已退出、来源材料仍有效、未生成最终报告且原 lease 未变化，才允许显式接管；旧状态按字节归档，新恢复使用独立 attempt，不能通过普通队列重复领取。

排队任务可由本人或明确授权者取消。运行中的任务未实现安全中断时必须明确拒绝取消，不能写入无人消费的取消标记并宣称已取消。成功、失败任务及追问数据均按既定保留期清理；维护恢复不能访问过期或跨任务材料。
