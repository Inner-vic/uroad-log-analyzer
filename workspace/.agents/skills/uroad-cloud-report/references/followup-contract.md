# Uroad 任务、并发与追问契约

## 任务身份

每个分析任务使用不可变 `job_id`，并记录：提问者、聊天、根消息/回复线程、源消息、VIN、时间范围、创建时间、状态与数据版本。飞书事件重试以 `message_id` 幂等；相同 VIN 和时间范围的另一条消息仍是新任务。

## 追问绑定

1. 回复报告所在的线程：绑定该线程的任务。
2. 消息包含 `#job_id`：绑定指定任务。
3. 缺少两者：只在调用方能证明当前仅有一个候选任务时才允许绑定；群聊中默认要求线程或编号。

访问规则：创建者可以在原聊天中追问；其他人只有在相同聊天、相同报告线程内才可追问共享任务。入口必须传递已验证的 Feishu 身份与消息元数据，不能让模型自行推断。

## 调度

- 每个任务按一个完整时间范围执行。`UROAD_MAX_HEAVY_JOBS`：重型任务最大并发，默认 `2`。
- `UROAD_MIN_FREE_GB`：启动重型任务前保留的最小剩余空间，默认 `20`。
- 同一任务追问按提交顺序串行；不同任务可以并行读取各自的数据。
- 排队任务按提问者轮询。槽位释放时，本地 worker 自动领取下一项。

## 数据保留

`UROAD_RETENTION_DAYS` 默认 `14`。任务目录在到期前包含原始下载、解析数据、报告、`run.json` 与 `followup-context.json`。到期后整个任务目录作为一个单元删除；追问收到“重新拉取需确认”的提示。

追问回答必须标记所用的 `job_id` 与 `dataVersion`。字段不在已有结构化结果中时，只能重解析该任务自身保留数据；不得跨任务取样或用自然语言臆测数据。
