# 公司 OpenClaw 云电脑部署与授权

此包是云端联调版，尚未经公司真实文档端到端验证。部署时沿用公司批准的 OpenClaw
运行环境和 Skill 安装目录，不改动现有 uroad Skill，不自行更换飞书插件或创建新应用。

## 先明确授权主体

你申请成功的可能是“账号可阅读这个文档”，也可能包含“允许该账号授权应用读取”。
两者需要区分；在保持现有文档权限的前提下选择一种云端访问身份：

| 路径 | 云端如何访问 | 还需要什么 |
|---|---|---|
| 用户身份（`--identity user`） | 使用已获文档访问权的企业账号，在云电脑为公司批准的应用完成 OAuth | 应用获准的只读 API scope、用户同意、有效的云端授权状态；不复制浏览器 Cookie |
| 应用身份（`--identity bot`） | 使用公司批准的应用自身身份 | 应用只读 API scope，以及文档所有者/管理员授予该应用的目标表格资源权限；个人账号权限不自动继承 |

长期无人值守优先与管理员讨论应用身份；初期联调可在公司允许时使用用户身份。
同一账号已获文档阅读权，不必仅因换到云电脑就重复申请同一文档权限；但需要核对
云端应用授权及设备/网络限制。OpenClaw 能收发飞书消息不代表已获 Sheets 读取权限。

“--identity user”是特定员工对该飞书应用的 OAuth 授权，不能转移给另一位员工。人员交接或
离职时，新职责人必须在同一 OpenClaw 运行环境以自己的企业账号重新完成公司批准的登录/授权，
并具备阿斯加德会话、结果表读取和所需最小 API scope；交接完成后撤销旧账号授权。不要复制旧员工
的浏览器 Cookie、CLI token 或密码。若必须长期无人值守，应由上游提供受控应用身份或正式服务接口。

应用身份与用户身份的数据范围有区别，见 [飞书官方 OpenClaw 接入指南](https://www.feishu.cn/content/article/7615520954977881029)。
企业“禁止下载/复制/导出”的具体含义以公司规则为准，不能推定 API 读取自动被允许。
公司若不允许读取接口，则停止这条链路，与上游对接只返回四个 P99 的获准接口。

## 部署人员准备

1. 将完整 `ad-p99-analysis` 目录安装到云电脑实际使用的 Skill 目录，保留 `scripts/` 和 `references/` 相对结构。
2. 在 OpenClaw **实际运行用户、容器及 Python 环境**中准备 Python 3.9+、`openpyxl==3.1.5`
   及公司批准的 `lark-cli`。包内有依赖声明，未附带离线依赖或 CLI 二进制；受限网络环境
   使用公司包源/部署流程准备，业务执行不联网安装依赖。本地核对的 CLI 为 1.0.85。
3. 复用获准的飞书应用配置，明确 user/bot 身份、API scope 和文档资源权限。
   不将 app secret、access token、refresh token 或真实文档写入 Skill 包、聊天或代码。
   授权状态由公司批准的 CLI/密钥存储管理；不会把凭据从个人电脑拷贝到云电脑。
4. 实际调用者和结果接收者需有权使用这些数据。共享用户身份的 Skill 不能开放给任意群成员。
   由 OpenClaw 接入层使用真实用户标识控制访问与投递；不能只靠提示词中的身份自称。
   模型服务、工具输出日志、备份和保留策略使用公司批准配置：云电脑在公司内部不等于模型接口也在内部。

安装 Skill 不会自动授予上述权限；此脚本也不修改授权、协作者或 OpenClaw 全局配置。

## 云端逐步验证

以下命令在云电脑的该 Skill 目录执行，使用与 OpenClaw 相同的运行身份。
真实 URL 只在公司环境输入，无需发回本地。

### 1. 环境检查（无文档请求）

```text
python scripts/check_environment.py
```

只检查 Python、openpyxl 和 CLI 版本，不登录、不读取文档或配置文件。
`status=ok` 且 `document_access=not_checked` 仅说明依赖存在，不代表已获得文档权限。

### 2. 授权准备（由公司部署流程执行一次）

应用身份应由管理员配置应用 scope 和目标文档资源访问，不执行用户 OAuth。
用户身份需在云端按公司允许的只读 scope 完成 OAuth；不是申请 `all`/写入/下载权限。
若公司已配置好可复用的授权，不重复登录。

若通过 `lark-cli` 交互授权，应按部署环境随附的 lark-shared 流程处理：
登录指定所需 scope，先输出授权链接/二维码给账号本人；等待本人完成后再在同一云端环境
完成设备授权。凭据刷新交由 CLI 管理；失效/撤销后返回授权错误，由账号本人恢复，
不切换到其他账号或复制登录态。具体 scope 以当前 CLI 对应只读操作所需权限为准。

### 3. 文档清单检查（不读单元格）

```text
python scripts/check_environment.py --sheet-url "<公司内部真实表格链接>" --identity user
```

使用应用身份时换成 `--identity bot`。只查询 revision 和工作表清单，输出目标 sheet 数量，
不回显文档 URL、完整清单、账号资料或 token。`metadata_readable` 仅证明这些元数据接口可访问，
`cell_access=not_checked` 明确表示尚未验证单元格权限。

### 4. 小样本业务验证

在公司许可读取接口的前提下，选一份已生成完成的结果表：

```text
python scripts/ad_p99.py --sheet-url "<公司内部真实表格链接>" --identity user
```

脚本只读取两个目标 sheet，在内存解析，输出四个 P99 及来源坐标，不导出文件，默认不落盘。
截图例子的预期值是 281.16、194.0、180.0、377.0 ms；验证其他报告应以该报告人工看到的值为准。
同时确认版本号稳定、返回坐标可对应、缺失值为 null，其他场景/原始整行数值没有进入输出。
`--output` 仅在公司明确允许存储摘要时使用，不能指向同步到个人电脑的位置。

### 5. Skill 调用验证

通过获准用户在公司 OpenClaw 中提供表格链接并请求“提取 AD P99 四场景时延”。
核对它调用的是本 Skill、使用已选身份、结果接收者正确，并且没有另行调用文档下载/导出工具。
成功退出码是 0；缺部分数据为 2；权限、配置、读取或解析失败为 1。
联调反馈优先提供失败阶段和脱敏结构，不提供内部文档、整表内容或凭据。

## 如何判断问题所在

| 现象 | 下一步 |
|---|---|
| 环境检查失败 | 部署人员补齐对应依赖或修正 OpenClaw 运行用户/路径 |
| 未配置应用或授权失效 | 在云端完成公司批准的配置/授权，不在本地索取凭据 |
| 账号在 UI 能看，API 报无权 | 核对 user/bot、应用 scope、文档资源权限及企业对 API/设备的限制 |
| 清单可读，正文失败 | 核对单元格接口权限和返回结构，清单成功不代表全链路成功 |
| 坐标/合并字段不符合预期 | 在公司环境保留脱敏 schema 供适配；不截断或猜测来凑数 |
| 读取期间版本改变 | 等上游完成并稳定后重新执行，不混用两个版本的数据 |

本地已完成合成数据测试；本文件列出的真实云端验证均未代执行。
