# uroad HTML 报告契约

## 交付物

- 报告阶段只生成 `report/uroad-report_<VIN>_<开始时间>_<结束时间>.html`，时间采用 `YYYYMMDD-HHMMSS` 格式；不生成 Markdown、`delivery.json`、静态图表资产或文档发布包。
- `manifest.json`、`analysis/analysis.json` 和 `run.json` 仅作为内部诊断及阶段契约，不得宣称为最终报告。
- `run.json.artifacts.report` 必须指向上述 HTML，且不得暴露其他报告格式或交付元数据。
- 流程成功后，`run.json.artifacts.report` 是附件交付的唯一权威路径。仅飞书触发的运行按照 [OpenClaw 附件交付契约](openclaw-attachment-delivery.md) 校验，并通过当前部署中**已验证、已授权**的附件发送入口交付到原会话；只有工具明确成功且消息结果含附件证据后才算完成。
- 校验或发送失败时保留 HTML 并报告交付失败，不得以普通文字分析、路径、Markdown 链接或 `MEDIA:` 文本代替附件，也不得声称已经交付。

## 生成与安全

- HTML 直接读取 `analysis.json`，不得依赖或解析中间报告。
- HTML 必须是 UTF-8 编码的单文件，内联 CSS、SVG、JavaScript 和必要展示数据；不得使用 CDN、远程请求、外部图片或静态资产目录。
- 报告必须保留曲线检查、缩放、平移、重置和键盘操作，并在无数据时明确显示“不可用”。
- 图表在鼠标指针位于绘图区时直接使用滚轮缩放，不要求 Ctrl/Meta 等组合键；图表之外的页面区域仍用于常规上下滚动。
- 报告不得携带凭据、原始日志或完整 `analysis.json`；未提供的事实不得猜测补齐。

## 内容要求

- 展示 VIN、文件数量、查询范围、总体结论、关键时间线、性能序列、问题与原因分布、CAN 信号和关键帧摘录。
- 关键时间线按分析结果原顺序完整展示；内容较多时放入自适应最大高度的纵向滚动窗口，不截断或抽样事件。
- 性能序列披露观测点数、展示点数、均值、最小值、最大值、事实来源和覆盖范围；降采样不得改变统计口径。
- CAN 曲线使用同一 VIN 和查询时间范围，包含车速、挡位和方向盘转角；挡位以语义标签和零阶保持展示。
- 需求文档中的挡位业务值为 D/R/P/N。日志或 CAN 中出现数字编码时保留原始值，不能描述为物理挡位，也不自动换算；报告提示当前数据表达与需求字段存在差异，并以权威 DBC/ARXML 为准。
- 问题、跳帧和异常原因使用面向工程师的中文说明并保留可核对编码；日志现象不得直接等同于预瞄悬架控制故障。

## 失败行为

- 本 Skill 的本地 `settings.json` 和非空 `username` 是强制配置；预检失败时必须在创建输出目录和发起网络请求前停止，并给出不含敏感信息的中文指引。
- uroad 或 CAN 获取失败、未找到 uroad 数据、或缺少必需 CAN 信号时，必须保留安全诊断状态并终止，不得生成 HTML 报告。
