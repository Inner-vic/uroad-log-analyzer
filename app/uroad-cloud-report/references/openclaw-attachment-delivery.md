# OpenClaw 飞书附件交付契约

本契约仅适用于由飞书会话触发且流水线成功生成 HTML 的报告交付。其他来源的请求不套用
飞书同会话/线程路由。流水线成功不是任务的最终完成条件；附件作为消息发送到原会话并
得到可核验的成功结果后，任务才完成。

流水线应由触发请求的同一次 OpenClaw 任务以前台方式执行并等待到退出。普通阶段状态写入
`run.json` 供诊断使用，默认不作为飞书消息发送。不要在发送“正在处理”一类消息后结束任务，
也不要依赖任务结束后的自动唤醒或后台回调完成附件交付。若执行工具返回可等待的会话标识，
应持续等待该会话；成功、失败、中断或平台超时都需要由当前任务给出一次最终结果。

## 建议执行顺序

1. 读取成功运行生成的 `run.json`，从 `run.json.artifacts.report` 取得本次唯一权威报告
   路径，不从控制台文字或约定文件名猜测路径。实际操作使用
   `cd /workspace && OPENCLAW_WORKSPACE=/workspace python /workspace/skills/uroad-cloud-report/scripts/validate_report_artifact.py --run-json "<主入口返回的 run 路径>"`，并只采用
   成功 JSON 的 `report` 字段；部署工作区不是 `/workspace` 时，先确认实际工作区，再替换命令中的路径和值；不临时编写 Python 内联脚本或 heredoc。
2. 分析前先确认当前部署里**已经验证、已经授权**的附件交付入口，并优先使用该入口发送本地文件；不要把判断范围限制为某一个回复工具 schema，也不要仅凭字段名猜测它支持本地文件。若当前部署没有已验证的附件发送入口，先向用户说明交付受阻，再决定是否需要调整配置或改用其他已授权方式。
3. 紧接发送前重新复核文件：解析真实路径并确认它是常规文件、可读且非空，扩展名为
   `.html`，真实路径仍包含在解析后的活动 `OPENCLAW_WORKSPACE`（未配置时为当前 OpenClaw
   工作区）中，大小未超过飞书媒体上限，并且文件开头具备基本 HTML 文档特征（例如
   `<!doctype html` 或 `<html`）。校验错误对用户隐藏绝对路径，只报告安全的运行标识、
   文件名和失败项。
4. 在同一次消息调用中携带结构化附件和简短、事实性的说明，并沿用触发本次
   运行的原飞书会话和线程；不要在附件调用成功后再发送第二条确认消息。
5. 仅当工具明确返回 success，且结果包含附件/file/media 标识或消息结果中有可核验的
   附件证据时才算完成。单独的上传成功、工具调用成功、打印路径或无证据响应都不证明
   附件消息已发送。HTML 位于工作区内不代表通道一定允许发送，仍需检查实际通道对路径、文件类型和大小的限制。

## 失败与重试

- 路径缺失、非常规文件、文件为空、扩展名或 HTML 特征错误、解析后位于工作区之外或
  文件过大时，指出脱敏后的具体失败项，暂缓上传，并保留运行目录和 HTML 供修正后重试。
- 如果飞书/OpenClaw 拒绝本地 `.html` 类型、路径访问或安全策略阻止访问，明确说明 HTML 附件被
  策略或通道限制拒绝。不要改用纯文字；转换格式、调整通道配置、绕过策略或上传云盘前先询问用户。
- 附件失败时保留报告和运行目录，只重试交付，不重新下载或重新分析。
- 模糊超时或无法确认是否已发送时不要自动重发，以免重复附件；说明状态未知并保留 HTML。
- 只有工具明确证明消息尚未发送且错误为瞬态时，才可使用同一权威路径和原会话/线程最多
  重试一次。策略、安全、路径访问或 HTML 类型拒绝不重试，先向用户说明可选择的后续处理方式。
- Markdown 链接、内联 `MEDIA:` 文本、浏览器/工具输出、文件路径或长篇摘要都不会替代
  结构化附件发送；请在收到明确发送确认后再说明交付成功。
