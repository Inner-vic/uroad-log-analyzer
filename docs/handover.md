# 项目交接手册

交接目标不是“把文件发给下一位”，而是让接手者能够独立完成一次定位、发布、回滚和故障处置。

## 1. 必须交付的资产

- 仓库地址、默认分支、保护规则和评审流程；
- 当前线上 `skillPath`、`VERSION`、commit/tag、发布包 SHA-256；
- OpenClaw 主机、工作区、输出目录和容量约束；
- prod/test 接口所有方、配置来源和凭据轮换流程；
- 飞书应用、机器人、附件发送入口和授权管理方式；
- 最近一次真实验收的 taskId/runId、日期、范围和结论；
- 当前告警、未完成 P0/P1、临时绕行和到期时间；
- 当前及上一版本的回滚制品。

敏感资产通过公司批准的秘密管理和权限系统交接，不写入本文件。

## 2. 接手演练

接手者应在原负责人旁观下完成：

1. 从全新 checkout 运行 82 项本地测试；
2. 识别 uroad、Supervisor、AD P99 的真实完成度；
3. 在隔离工作区验证离线运行时；
4. 使用获授权测试 VIN 完成短时间窗查询；
5. 校验、发送、下载并离线打开 HTML；
6. 模拟附件失败，只重试交付；
7. 执行 retention dry-run 并解释每类候选；
8. 演练回滚到上一版本；
9. 说明凭据泄露、跨用户串联和错误环境取数的升级路径。

## 3. 交接验收

| 检查项 | 证据 | 结果 |
|---|---|---|
| 本地测试 | 命令和通过数量 | 待填写 |
| 当前部署版本 | 路径、版本、哈希 | 待填写 |
| 真实短案例 | taskId/runId 与附件回执 | 待填写 |
| 回滚演练 | 恢复版本和验证记录 | 待填写 |
| 权限交接 | 新账号验证、旧授权撤销 | 待填写 |
| 监控与清理 | 巡检和 dry-run 记录 | 待填写 |
| 未决风险 | owner 与截止日期 | 待填写 |

所有项目通过后，双方更新 [`MAINTAINERS.md`](../MAINTAINERS.md)。若关键平台代码或权限无法获得，必须把它记录为阻断项，不得以口头承诺代替。
