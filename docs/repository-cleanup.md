# 目录整理说明

## 整理结果

仓库现在以 `app/` 为唯一可提交应用源码区。原目录尚未建立 Git 历史，直接永久删除旧源码和约 9.8 GB 运行材料存在不可恢复风险，因此本轮采用“复制可信基线 + Git 隔离”的方式。

以下本机目录和文件由根 `.gitignore` 排除，不会进入新仓库：

- `runs/`、`uroad-report-runs/`、`live-test-*`：真实运行数据和报告；
- `archive/`、`deploy/`、根归档包：旧副本和发布制品；
- 根级旧 uroad 代码、拆分前 Skills、旧 Supervisor/AD P99：历史或重复实现；
- `_bmad*`、`.agents/`、`.claude/`、`research/`：本地工作流和研究材料；
- 个人简历、登录二维码、真实 `settings.json`：个人或敏感内容。

## 建议的物理清理时机

完成以下条件后再删除本地遗留材料：

1. 新 Git 仓库已创建首个备份或已推送到受控远端；
2. `app/uroad-cloud-report/VERSION` 与目标版本一致；
3. 统一测试通过；
4. 原始基线制品已转存到受控制品库且 SHA-256 可核验；
5. 确认不再需要真实运行数据进行事故、合规或回归追溯；
6. 凭据已轮换，旧二维码和个人 OAuth 已失效。

物理清理时应使用明确绝对路径逐目录处理，先生成清单和大小，禁止对工作区根目录执行递归通配删除。
