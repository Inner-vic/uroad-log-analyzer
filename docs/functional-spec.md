# 功能说明

## 1. 应用定位

Uroad Log Analyzer 是车辆日志智能分析应用开发项目。当前核心能力接收 VIN、时间范围和目标环境，获取同环境 uroad 与 CAN 数据，生成可追溯的离线 HTML 报告，并通过 OpenClaw/飞书交付。

应用不是通用日志平台，也不是一个独立 Web 服务。它由部署到 OpenClaw 的 Python Skills、平台消息入口和外部数据接口共同组成。

## 2. 使用对象

- 测试与问题分析人员：提交查询并阅读报告；
- 应用开发人员：维护任务、解析、报告和路由代码；
- 平台运维人员：维护 OpenClaw、飞书身份、配置、发布和运行目录；
- 接口所有方：维护车云 prod/test 可用性和数据定义。

## 3. 当前核心功能

| 编号 | 能力 | 已实现行为 |
|---|---|---|
| F-01 | 请求规范化 | 校验 VIN、开始/结束时间与 `Asia/Shanghai` 时间语义 |
| F-02 | 任务注册与复用 | 使用请求键查重；运行中任务不重复启动；合法完成报告可复用 |
| F-03 | 环境选择 | 支持 `prod`、`test`、`auto`；测试环境映射为 provider `testtwo` |
| F-04 | uroad 数据获取 | 查询 `log_fsdA_service` 并解析帧、耗时、FPS、跳帧和异常 |
| F-05 | CAN 数据获取 | 查询 `msg_xcu`，流式处理 EEA3 数据并提取目标信号 |
| F-06 | 资源控制 | 15 分钟切片顺序处理；单片 uroad/CAN 两通道并发；重流水线单实例 |
| F-07 | 报告生成 | 生成单个自包含 HTML，包含概览、时间线、图表、原因和关键证据 |
| F-08 | 产物门禁 | 只允许当前 run 的合法 HTML 路径进入交付流程 |
| F-09 | 交付回写 | 只有明确消息成功结果才记录 `sent`；单纯上传不算送达 |
| F-10 | 保留清理 | 按任务状态和期限清理原始文件、诊断证据和历史报告 |

## 4. 数据和判定规则

- 一份报告的 uroad 与 CAN 必须来自同一 `resolvedEnv`。
- `auto` 只有在生产请求成功但目标数据为空或不完整时才允许整单回退测试环境；认证、网络、5xx 或响应结构错误不得回退。
- uroad 是主数据源；整个范围没有 uroad 时不生成业务报告。
- CAN 目标为 `0x12A`、`0x108`、`0x106` 中定义的 `vehicleSpeed`、`gear`、`steeringAngle`。
- 结论只描述日志可观察事实。业务现象不能直接写成根因，未观察到异常也不等于异常不存在。
- 报告补发只重试交付，不重新下载或分析。

## 5. 能力成熟度

| 单元 | 已实现 | 已测试 | 已部署/验收边界 |
|---|---|---|---|

## 6. 非功能要求

- 8 GB 主机上避免全量数据驻留内存；
- 任务状态和运行产物可由 taskId/runId 追踪；
- 配置、凭据和内部 JSON 不进入用户报告；
- 最终 HTML 不依赖外部 CSS、JavaScript 或图片；
- 重试、恢复和清理不得制造重复重任务或删除活动任务；
- 用户隔离和管理操作需要可靠身份与审计。

## 7. 当前不包含

- 独立 Web UI、HTTP 服务或数据库服务；
- Supervisor 的完整生产执行器；
- 自动获取或转移个人 OAuth；
- 对 ARM64、Alpine/musl、PyPy 或 Windows 的生产离线运行支持；
- 未经授权的跨群聊报告复用、任务取消或数据公开。
